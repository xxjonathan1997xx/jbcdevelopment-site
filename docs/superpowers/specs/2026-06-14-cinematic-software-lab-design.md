# Cinematic Software Lab Homepage Design

## Objective
Refresh the JBC Development homepage from the current clean software-lab look into a more intriguing, cinematic software lab while keeping the company focused on software development, apps, local Mac tools, AI workflows, automation, downloads, support, and privacy.

This is a visual and interaction refresh only. It does not add a backend, tracking, analytics, cloud services, forms, data capture, billing, ads, affiliate links, or product claims.

## Approved Direction
Use the selected visual direction: **A. Cinematic Software Lab**.

The site should feel darker, sharper, more technical, and more memorable above the fold. It should still read as professional software-company positioning, not a creator page, agency-services page, or experimental art page.

## Homepage Changes

### Hero
- Shift the first viewport toward a deeper navy software-lab environment.
- Keep the JBC Development brand and software message as the main focus.
- Replace the current plain-feeling hero tone with stronger contrast, a more dimensional workbench, and a more compelling headline.
- Preserve two primary actions: view software and downloads.
- Keep the hero practical and readable on desktop and mobile.

### Software Workbench
- Make the hero media feel more alive with layered lab panels, code/activity lines, app tiles, and release/status cues.
- Keep all animation subtle and purposeful.
- Maintain stable dimensions so animation does not cause layout shift.

### Section Rhythm
- Keep the existing content structure: process, build pipeline, apps, projects/resources, DadBuildRepeat personal block, support/contact.
- Make process and pipeline sections feel like parts of a real software release system.
- Make app cards feel more product-like and more visually connected to the lab theme.

### Personal Channel
- Keep DadBuildRepeat visually secondary.
- Keep TikTok, Instagram, YouTube, and Facebook links.
- Do not make DadBuildRepeat the primary homepage story.

## Motion
- Add or refine code scan, app tile pulse, build rail activity, and section reveal motion.
- Respect `prefers-reduced-motion`.
- Avoid motion that blocks reading, causes layout shift, or feels gimmicky.

## Constraints
- Static HTML, CSS, and vanilla JavaScript only.
- No build system changes.
- No backend changes.
- No public deployment until separately confirmed.
- No services/client-work positioning.
- No new claims about sponsorships, revenue, customers, certifications, or affiliate status.
- No data collection or tracking additions.

## Verification
- Run `node --check script.js`.
- Run `git diff --check`.
- Verify local desktop and mobile layouts in the browser.
- Confirm no horizontal overflow.
- Confirm no console warnings/errors.
- Confirm `prefers-reduced-motion` remains supported.
- Confirm nav, app links, downloads, support, privacy, EN/ES switching, and personal social links still work.
- Confirm JBC software remains the main message above the fold.

## Deployment
Implementation is local only until Jonathan separately confirms live deployment.
